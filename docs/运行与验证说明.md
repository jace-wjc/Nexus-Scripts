# 运行与验证说明

本文件描述当前代码的运行合同。测试通过、容器健康、业务验收和生产验收分别记录；不要互相替代。

## 环境与依赖

- Node ≥22.3.0，Docker/CI 使用 22.x；npm ≥10。当前安全补丁为 Next 15.5.24、React/React DOM 19.1.9、eslint-config-next 15.5.24。
- CI/Docker 使用 `npm ci`。保留 npm/pnpm 两份锁文件；依赖改动应同步核对，不删除锁文件解决安装失败。不要混用已有 node_modules。
- `next lint` 在本项目 Next 15.x 仍存在。类型检查用 `npm run typecheck -- --incremental false`；行为测试用 `node --test 'src/**/*.test.mjs'`；ESLint 范围以修改文件和 CI 配置为准。构建忽略 ESLint，不等于 lint 通过。
- 后端 Docker Python 3.12、CI Python 3.11；本次本机验证使用 Python 3.13.13，不能据此声称其他解释器已经实测。
- 启动后端会执行现有 schema 维护、任务恢复和调度逻辑。禁止为只读检查启动一个指向业务库的副本。

## 本地启动与长连接

前端在 `my-app` 执行 `npm run dev`；后端在 `fastApiProject` 执行 `venv/bin/python run.py --reload`。Windows 使用对应 venv 解释器。

`run.py --graceful-timeout 30` 限制退出时等待在途请求的时间，默认 30 秒。达到期限会取消仍未结束的 SSE，请浏览器重连补查状态。它不能保证所有同步后台工作在 30 秒内终止，也不能替代持久任务恢复。Gunicorn 的超时配置仍需在部署环境验证。

构建前确认服务进程和工作目录：不能让 dev 和 build 同时写同一 `.next`。可以在仅包含源码和合成数据的独立目录构建。更新 node_modules 前停止使用它的服务。不要清理运行中产物或终止无关服务。

## 验证隔离与发布门禁

普通后端检查从 `fastApiProject` 执行：

```bash
venv/bin/python scripts/run_isolated_tests.py tests/ -p no:randomly -q -W error::Warning
venv/bin/python scripts/run_isolated_tests.py tests/ --randomly-seed=20260910 -q -W error::Warning
```

解释器需安装项目声明的开发测试依赖，包括 pytest-randomly。隔离脚本复制源码到临时目录，不复制环境文件、上传、资源数据、日志或符号链接；测试只得到合成配置，外部网络连接被拒绝。输出目录和 pytest.log 会保留，以便比较具体失败集合。测试结束后确认工作区未出现业务文件副作用。

完整门禁要求新建专用本机 MySQL 实例或专用测试库，库名以 `nexus_gate_` 开头。显式提供 `NEXUS_MYSQL_TEST_ISOLATED=1` 和全部 `DB_LOCAL_HOST/PORT/USER/PASSWORD/DATABASE`；不要加载业务 `.env`。账户只能访问专用库，主机只允许回环地址。使用配置持有者提供的隔离凭据，不将密钥写进脚本、报告或历史。

```bash
# 先在当前进程注入上述专用验证配置；此命令不能在业务配置下执行。
bash scripts/run_release_gate.sh
```

门禁依次执行固定顺序 SQLite、记录随机种子的 SQLite、两次独立进程 schema 检查、真实 MySQL 双会话及跨进程锁专项。MySQL 缺失时必须失败，不得将专项跳过标记为整体验证通过。测试默认跳过 MySQL 仅适用于前两阶段。

本机 MySQL 9.0.1 的结果不等于 CI MySQL 8.0 的结果；CI 必须继续运行其真实 MySQL 服务容器。不要更改业务数据库来满足测试种子。

## 持久化与首次升级

| 配置 | 本地未配置时 | Compose 运行时 |
|---|---|---|
| RESOURCE_LOGO_ROOT | my-app/public 下的 team-logos、ai-logos | /app/runtime-logos，resource_logos 卷，UID/GID 1001 |
| TEAM_RESOURCES_BACKUP_DIR | 原 my-app/data 目录 | /app/data/team-resource-backups，处于现有后端 bind mount 内 |

Logo 原 URL 保留，动态读取使启动后新增文件立即可用。先读运行目录，再读镜像中的旧图片；删除标记避免旧图回退后重新出现。该读取端点只服务图像文件，不能用来读取资源凭据。已有资源密文、加密格式和加密密钥保持不变。

**首次切换前必须单独确认存量复制方案。** 对旧运行容器中的 public/team-logos、public/ai-logos，以及旧后端 `/my-app/data/team-resources.enc.json` 只读盘点。复制到新持久化路径前保留原件；复制后核对数量、大小和 SHA-256，并在隔离环境验证旧密文可解密。禁止打印解密内容，禁止重新加密存量文件。前端目标目录需允许 UID/GID 1001 读写。

deploy.sh 检测到旧容器可能包含未迁移文件，或容器无法检查时会停止。只有在完成获批复制与核对之后，才能设置 `PERSISTENCE_MIGRATION_CONFIRMED=1` 进行首次部署。不要把这个开关作为跳过数据保护的通行证。当前代码变更没有迁移真实文件。

## 配置与凭据

Compose 在运行时注入凭据，环境文件被根构建上下文和后端构建上下文排除。Windows start_all.bat 要求启动环境已提供 AGENT_API_KEY，不再携带字面量。`.env.example` 仅为键名和占位值。

当前受 Git 跟踪的环境文件及历史中的凭据尚未治理。停止跟踪、历史清理、会话签名轮换、外部凭据轮换、资源加密密钥轮换须分别批准；删除当前文件不能清除历史。资源加密密钥不得直接替换，否则可能失去旧密文解密能力。

## 健康与发布

- `/health/live` 只报告进程响应；`/health/ready` 检查启动已完成、调度器运行和 `SELECT 1`，不初始化数据或发起任务。
- schema 锁未取得、必要列/索引失败、初始化失败会阻止正常就绪。不要通过吞异常来恢复绿灯。MySQL DDL 可能已经部分提交，应先查看具体失败步骤再重跑。
- deploy.sh 是实际发布脚本，会检查工作区、拉取代码、构建和重建容器。普通验证不应执行它。
- 部署需支持 `compose up --wait` 的 Docker Compose 和 curl。`DEPLOY_WAIT_SECONDS` 默认 300 秒；`DEPLOY_SMOKE_BASE_URL` 默认本机 8090。脚本等待容器健康、通过 Nginx 检查后端就绪，并核对前端 commitSha。
- 这些检查通过后仍需授权的业务冒烟：登录、岗位/候选人读取、细粒度权限、SSE、合成文件上传下载和外部服务替身。禁止用真实结算、发信或模型费用作为默认冒烟。

## 回滚

1. 保留旧镜像、当前源码版本和获批的数据库/文件备份。未提交工作区不要使用整文件 checkout、reset 或 stash 覆盖用户修改；按补丁撤销本批自有变更。
2. 前端依赖需要回退时，成组恢复 package.json 和两份锁文件，在停止前端后执行对应安装，使用独立构建目录重建。旧漏洞版本只用于受限环境恢复，不应继续公开运行。
3. Logo 与备份切回旧配置前保留新旧路径和删除标记。禁止 `docker compose down -v`、删卷或删除运行目录。代码回退不会把新文件自动复制回旧容器。
4. MySQL 已执行的 DDL 不会随代码回退撤销。当前补丁没有新增业务 DDL，但原有 schema 维护仍会执行现有操作；失败时记录完成步骤，使用备份恢复须单独批准并演练。
5. 外部结算、邮件、短信或模型调用不能靠代码回退撤回。权限和文件边界修复发生兼容问题时，应隔离受影响入口，不能恢复匿名写库或公开敏感下载。
